# 주간 유튜브 성과 → AI에게 넘기는 자료 (템플릿)

목적: **어떤 숏이 상대적으로 잘 됐는지 / 아쉬웠는지**를 한 번에 정리해 두고, 같은 내용으로 챗 AI에게 요청할 때 맥락을 잃지 않게 한다.  
(파일을 채워 저장한 뒤 Cursor에서 `@docs/weekly-youtube-review-handoff.md` 로 참조하거나, 해당 주차만 복사해 채팅에 붙여 넣어도 된다.)

---

## 1. 넘기면 좋은 것들 (체크리스트)

아래 중 **있는 만큼** 적을수록 피드백이 구체해진다.

| 항목 | 왜 필요한가 |
|------|-------------|
| **기간** | 예: `2026-05-06 ~ 2026-05-12` (주간 비교 기준 통일) |
| **영상별 식별** | `video_id`, 또는 스튜디오 URL, 또는 로컬 `output/…/result.json` 의 `topic` |
| **패키징** | 업로드 시 **제목**, **훅/썸네일 카피**(있으면), **토픽 한 줄** |
| **숫자** | 업로드 후 **7일** 또는 **28일** 조회수(또는 주간 증가분); **조회수를 1순위 KPI로 둘 때** 같은 표에 **노출**, **CTR(클릭률)** 을 두면 패키지 vs 스크립트를 분리하기 쉽다. 선택: **평균 시청 비율 / 도달** |
| **스냅샷 규칙** | 업로 시간이 다른 영상이라도 **동일 시간 경과**(예: 업로 후 48h·7일) 또는 **같은 날 작성한 표**처럼 맞춰 적으면 주간 비교가 공정하다 |
| **상대 평가** | 이번 주 업로드분 중 **상위 3 / 하위 3**(또는 상·중·하)만이라도 |
| **주관 메모** | “첫 두 문장이 약했다”, “사건 이름은 좋았는데 끝이 범용적이었다” 등 **한 줄** |
| **변경 실험** | 이번 주에 바꾼 것: 예) BOOKEND 프롬프트 적용, 업로드 시간, 장르 토픽 성격 |
| **다음 주 질문** | 예: “훅만 짧게 할까, 중간 한 문장을 줄일까” 같이 **결정하고 싶은 것** |

숫자는 Studio에서 CSV 내보내기·스크린샷 대신 **직접 붙여 넣은 표**만 있어도 충분하다.

---

## 1b. 조회수 우선일 때 표에 넣기 좋은 열

| 열 이름 (권장) | 설명 |
|----------------|------|
| `video_id` | 스튜디오·DB(`published_topics.video_id`)와 매칭 |
| `제목` | 패키지와 즉시 대비 |
| `topic (raw)` | 한 줄 주제 (`raw_topic`, `output/…/result.json` 등) |
| `HOOK 첫 문장` | 각본 도입 한 문장만 — 같은 사건·재업 편 비교에 유용 |
| `업로일` | |
| `길이(초)` | 선택 |
| `노출` | 해당 스냅샷 구간 노출 수 |
| `CTR %` | Studio 표기 그대로(없으면 비움) |
| `조회수` | 1순위로 보는 수치 (**스냅샷 조건은 메타에 적기**) |

## 2. 복사해서 쓰는 템플릿

아래 블록을 복사해 `docs/reviews/YYYY-Www-review.md` 같은 경로에 저장하거나, 주간마다 새 파일로 두어도 된다.

```markdown
## 메타
- 채널 / 장르: (예: 미스터리 숏)
- 기간: YYYY-MM-DD ~ YYYY-MM-DD
- KPI: 조회수 1순위(권장: 같은 행에 노출·CTR로 패키지 맥락 보충)
- 숫자 스냅샷: 예) 업로 후 7일 / 또는 표를 적은 당일 고정 규칙
- 이번 주 실험·변경사항: (프롬프트 / 썸네일 / 업로드 시간 등)

## 영상 목록 (이번 주 업로드)

| video_id | 제목 | topic (raw) | HOOK 첫 문장 | 업로일 | 길이(초) | 노출 | CTR | 조회수 | 메모 |
|----------|------|-------------|--------------|--------|----------|------|-----|--------|------|
| | | | | | | | | | |

## 상대 성과
- 잘 된 편 TOP: (video_id 또는 제목) — 이유 한 줄:
- 아쉬운 편: — 이유 한 줄:

## 다음 주에 바꾸고 싶은 것 (후보)
1.
2.

## AI에게 부탁하고 싶은 것
- 예: prompts/mystery.txt 의 STRUCTURE 중 ○○만 수정안 제안
- 예: 상위작 공통점 / 하위작 공통점 bullet 요약
```

## 3. 채운 예시 (가상 데이터)

```markdown
## 메타
- 채널 / 장르: 미스터리 숏 (US)
- 기간: 2026-05-06 ~ 2026-05-12
- KPI: 조회수 1순위 (노출·CTR 같은 행 권장)
- 숫자 스냅샷: 예) 업로 후 7일 시점 또는 표 작성 일자 규칙 통일
- 이번 주 실험·변경사항: BOOKEND 프롬프트 반영 후 첫 주

## 영상 목록

| video_id | 제목 | topic (raw) | HOOK 첫 문장 | 업로일 | 길이(초) | 노출 | CTR | 조회수 | 메모 |
|----------|------|-------------|--------------|----------|----------|------|-----|--------|------|
| abc123 | The Dyatlov tents… | Dyatlov Pass… | A documented anomaly near the tents… | 2026-05-07 | 32 | — | — | 12000 | 첫 증거 훅 강함 |
| def456 | She vanished from… | Elisa Lam… | The elevator footage shows… | 2026-05-09 | 30 | — | — | 4100 | 제목은 검색 친화적이나 CTR 낮았던 느낌 |

## 상대 성과
- TOP: abc123 — 오프닝이 구체 증거였고 끝이 같은 증거로 회귀.
- 아쉬움: def456 — 중간이 길어져 클램프로 잘린 느낌.

## 다음 주 후보
1. 유명 사건일수록 HOOK를 더 짧게 (한 문장으로 제한 시험)
2. 나쁜 편만 재생 목록으로 묶어 썸네일만 교체 테스트

## AI에게 부탁
- 상위 vs 하위 차이를 스크립트 구조 관점에서만 5줄로 요약하고, mystery.txt 수정 초안 제안
```

## 4. 이 파일을 어떻게 활용하면 좋은지

1. **Cursor 채팅**  
   - 매주 템플릿을 채운 뒤 **파일을 저장**하고, 새 채팅에서 `@docs/weekly-youtube-review-handoff.md` 와 함께  
     “이번 주는 `docs/reviews/2026-W19.md` 내용 반영해서 …” 처럼 **구체 파일을 하나 더 지정**하면 더 좋다.

2. **요청 예시 문장**  
   - “위 표 기준으로 상위·하위 공통점만 추려 줘.”  
   - “BOOKEND 규칙 유지前提下에서 하위작만 고치려면 프롬프트 어디 한 줄을 어떻게 바꿀지 제안해 줘.”  
   - “다음 주 실험 1개만 고르면 뭐가 표본 대비 깔끔할지 추천해 줘.”

3. **저장 위치 습관**  
   - 주차별 파일: `docs/reviews/2026-W19-review.md` — 나중에 “3주 전 대비 문구 변경 효과”를 같은 형식으로 비교하기 쉽다.

4. **한계 인지**  
   - 조회만 보면 스크립트 때문인 것처럼 보일 수 있다. 같은 표에 **노출·CTR**을 두고, **토픽·HOOK 첫 문장**을 채워 두면 개선 레버가 나뉜다.

---

## 5. AI가 코드를 바꿀 때 같이 주면 좋은 것

- 해당 주에 생성된 **`metadata.json` 일부**(title, topic) 또는 `result.json` 의 `topic`, `videoId`
- Supabase `published_topics`: `raw_topic`, **`hook_first_line`**, **`thumbnail_line`**, `video_id`(업로드 성공 시 이후 행부터 채워짐 — 기존 행은 마이그레이션만 적용됨)
- “이번에만 적용하고 싶다”는 범위: 예) `prompts/mystery.txt` 만 / `generateMetadata` 도

이 문서는 **운영 가이드**이며, 파이프라인이 자동으로 이 파일을 읽지는 않는다.
